# Contributing to Join UI

Thanks for being here. Join UI is an open-code catalog: every component in
`registry/components/` is shipped as real source into other people's projects,
so a contribution here lands directly in someone's codebase. That is the bar
this guide describes.

The full walkthrough — component anatomy, house rules, MDX authoring, the AI
prompt — lives in the docs at **[/docs/contributing](https://ui.join-way.com/docs/contributing)**
(source: `content/docs/contributing.mdx`). This file covers the parts that are
about the repository rather than the code.

---

## Getting set up

Requires **Node.js 20.9+** and **pnpm 10+**.

```bash
git clone https://github.com/d1maash/join-ui.git
cd join-ui
pnpm install
pnpm dev
```

Open <http://localhost:3000>.

Run everything the CI runs before you push:

```bash
pnpm check   # registry:validate + typecheck + lint
pnpm build   # regenerates the registry, then builds
```

## What to work on

| You want to…        | Start with                                                                   |
| ------------------- | ---------------------------------------------------------------------------- |
| Add a component     | [/docs/contributing](https://ui.join-way.com/docs/contributing) — four files |
| Fix a bug           | Open an issue first if the fix changes a component's public API              |
| Add or correct docs | `content/docs/*.mdx` plus an entry in `lib/docs/nav.ts`                      |
| Propose a component | Open a **Component request** issue — sketch the API, not the code            |

For anything larger than a bug fix, open an issue before writing code. A
component that does not fit the design system is a painful thing to reject
after it has been built.

## Workflow

1. Fork, then branch off `main`. Name the branch for the work:
   `feat/glow-card`, `fix/timeline-focus-ring`, `docs/theming`.
2. Commit in the imperative mood, describing the change rather than the
   files touched — `Add Focus Stack`, not `update components.ts`. Small,
   self-contained commits review far better than one large one.
3. Run `pnpm check` and `pnpm build`.
4. Open a pull request against `main` and fill in the template.

Pull requests are squash-merged, so the PR title becomes the commit on `main`.
Write it accordingly.

## Before you open a pull request

- `pnpm check` passes — validation, types and lint.
- `pnpm build` succeeds.
- The component works with a keyboard alone.
- It behaves correctly with Reduce Motion enabled at the OS level.
- Both preview themes look right — check with the sun and moon buttons on the
  preview frame, not just by switching the site theme.
- No `dark:` variants in `registry/` or `components/previews/`.
- No hard-coded colours, no gradients, no invented shadows. Hue comes from the
  four token families, and corners round through `rounded-soft*`.
- No `any`, and no `TODO` left in place of an implementation.

The reasoning behind each of these is in the docs — [theming](https://ui.join-way.com/docs/theming),
[dark mode](https://ui.join-way.com/docs/dark-mode) and
[accessibility](https://ui.join-way.com/docs/accessibility).

## The separation that matters

| Directory              | Rule                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| `registry/components/` | Ships to other people's projects. May only import `react`, its declared npm dependencies, and `@/lib/utils`. |
| `components/previews/` | Demos. Never leave this site, so they may import anything — but the `dark:` ban still applies.               |
| `components/site/`     | Documentation chrome. Never shipped by the registry.                                                         |
| `components/ui/`       | Local primitives for the docs. Deliberately separate from registry components.                               |

Never hand-write `registry.json` or anything under `public/r/` — both are
generated by `pnpm registry:build` from `lib/registry/components.ts`.
