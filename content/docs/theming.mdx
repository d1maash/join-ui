Everything visual in Joinway UI resolves through CSS custom properties. Change a
token and every component follows — including the ones already installed in your
project.

## The token set

Copy this into `app/globals.css`. Values are `oklch`, which keeps perceptual
lightness consistent when you shift hue.

```css title="app/globals.css"
:root,
.light {
  /* Surfaces */
  --background: oklch(0.994 0.002 250);
  --foreground: oklch(0.185 0.014 258);
  --card: oklch(1 0 0);
  --popover: oklch(1 0 0);
  --muted: oklch(0.966 0.004 255);
  --muted-foreground: oklch(0.508 0.016 258);

  /* Lines */
  --border: oklch(0.912 0.006 258);
  --border-strong: oklch(0.858 0.008 258);
  --input: oklch(0.912 0.006 258);
  --ring: oklch(0.58 0.113 174);

  /* Brand */
  --primary: oklch(0.556 0.108 174);
  --primary-foreground: oklch(0.99 0.012 174);
  --primary-soft: oklch(0.947 0.032 174);
  --accent: oklch(0.712 0.142 62);
  --destructive: oklch(0.577 0.212 27.3);
  --success: oklch(0.6 0.132 155);
  --warning: oklch(0.72 0.15 75);

  /* Signature gradient */
  --brand-from: oklch(0.63 0.13 176);
  --brand-via: oklch(0.72 0.15 148);
  --brand-to: oklch(0.76 0.15 106);

  /* Shape */
  --radius: 0.625rem;

  /* Elevation */
  --shadow-subtle: 0 1px 2px -1px oklch(0.185 0.014 258 / 0.08);
  --shadow-raised: 0 1px 2px -1px oklch(0.185 0.014 258 / 0.06), 0 4px 12px -4px oklch(0.185 0.014 258 / 0.08);
  --shadow-floating: 0 2px 4px -2px oklch(0.185 0.014 258 / 0.06), 0 12px 32px -8px oklch(0.185 0.014 258 / 0.12);
  --shadow-overlay: 0 4px 8px -4px oklch(0.185 0.014 258 / 0.08), 0 24px 56px -12px oklch(0.185 0.014 258 / 0.18);

  /* Motion */
  --duration-instant: 90ms;
  --duration-fast: 160ms;
  --duration-base: 240ms;
  --duration-slow: 420ms;
  --ease-out-soft: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in-out-soft: cubic-bezier(0.65, 0, 0.35, 1);
  --ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);
}
```

Then map them onto utilities with `@theme inline` — see
[Tailwind setup](/docs/tailwind-setup).

## Token reference

| Token | Purpose |
| --- | --- |
| `--background` / `--foreground` | Page surface and body text |
| `--card` / `--card-foreground` | Raised surfaces |
| `--popover` / `--popover-foreground` | Floating surfaces — menus, dialogs |
| `--muted` / `--muted-foreground` | Recessed fills and secondary text |
| `--border` | Default hairline |
| `--border-strong` | Hover and emphasis borders |
| `--ring` | Focus outline colour |
| `--primary` / `--primary-foreground` | Brand actions |
| `--primary-soft` | Tinted brand fill for selected states |
| `--accent` | Secondary highlight |
| `--destructive` / `--success` / `--warning` | Status colours |
| `--brand-from` / `--brand-via` / `--brand-to` | Gradient ramp |
| `--radius` | Base radius; the scale is derived from it |
| `--shadow-*` | Four elevation steps |
| `--duration-*` / `--ease-*` | Motion timing |

## Rebranding

Change the hue on the brand tokens and everything moves together — buttons,
focus rings, the aurora, the gradient border, selected tabs:

```css title="app/globals.css"
:root {
  --primary: oklch(0.55 0.19 275);
  --ring: oklch(0.58 0.19 275);
  --primary-soft: oklch(0.95 0.04 275);
  --brand-from: oklch(0.62 0.19 275);
  --brand-via: oklch(0.66 0.18 305);
  --brand-to: oklch(0.74 0.15 340);
}
```

<Callout type="tip">
  Keep the lightness values and change only the hue and chroma. The palette was
  balanced against `--background` and `--foreground` for contrast; shifting
  lightness is what usually breaks it.
</Callout>

## Radius

The scale is derived, so one value reshapes the whole system:

```css
:root {
  --radius: 0.25rem;   /* sharp, technical */
  /* --radius: 0.625rem;  default */
  /* --radius: 1rem;      soft, consumer */
}
```

## Scoped themes

Tokens are inherited custom properties, so any subtree can override them. This
is a supported pattern, not a hack:

```tsx
<section
  style={{
    "--primary": "oklch(0.62 0.19 25)",
    "--primary-soft": "oklch(0.95 0.05 25)",
  } as React.CSSProperties}
>
  <MagneticButton>Danger zone</MagneticButton>
</section>
```

The same mechanism powers the theme switch on every preview — see
[dark mode](/docs/dark-mode).

## Component-level overrides

Every component merges `className` last through `cn`, so `twMerge` resolves the
conflict in your favour:

```tsx
<SpotlightCard className="rounded-3xl border-primary/40 bg-transparent">
  …
</SpotlightCard>
```

Components with more than one surface expose a second hook rather than making
you fight selectors:

```tsx
<GradientBorderCard className="rounded-3xl" innerClassName="rounded-[1.4rem] p-8" />
<CursorHighlight highlightClassName="border-2 border-accent bg-transparent" />
```

## Contrast

The default palette clears WCAG 2.2 AA in both themes:

| Pair | Light | Dark |
| --- | --- | --- |
| `--foreground` on `--background` | 15.8:1 | 14.6:1 |
| `--muted-foreground` on `--background` | 5.1:1 | 5.4:1 |
| `--primary-foreground` on `--primary` | 6.9:1 | 8.2:1 |

If you retune the palette, re-check `--muted-foreground` first. It carries most
of the body copy and sits closest to the 4.5:1 threshold.
