Everything visual in Joinway UI resolves through CSS custom properties. Change a
token and every component follows — including the ones already installed in your
project.

## The principle

The palette is achromatic. Every colour token is declared in `oklch` with a
chroma of exactly zero, so the interface can only ever render in black, white
and the grey ramp between them. A token with chroma in it is a bug, not a
variation.

That constraint moves the work somewhere more durable. Meaning is carried by
weight, rule thickness, size and spacing — never by hue. A destructive control
is not red; it is the one control set in inverted ink. A warning is not amber;
it is an aside with a thicker left rule, an icon, and the word spelled out.

Two consequences are worth stating up front, because they are what most people
expect to find and will not:

- There are no gradients in the system and no elevation tokens. Depth is drawn
  with hairlines, not with shadow.
- `--radius` is `0rem` and every step of the radius scale resolves to zero.
  Corners are square.

## The grey ramp

The ramp is the only palette. Twelve steps, from paper to ink, and every
semantic token below is an alias onto one of them.

```css title="app/globals.css"
:root,
.light {
  --grey-0: oklch(1 0 0);
  --grey-50: oklch(0.975 0 0);
  --grey-100: oklch(0.95 0 0);
  --grey-200: oklch(0.9 0 0);
  --grey-300: oklch(0.82 0 0);
  --grey-400: oklch(0.68 0 0);
  --grey-500: oklch(0.55 0 0);
  --grey-600: oklch(0.44 0 0);
  --grey-700: oklch(0.32 0 0);
  --grey-800: oklch(0.22 0 0);
  --grey-900: oklch(0.13 0 0);
  --grey-1000: oklch(0 0 0);
}
```

In `oklch` the first component is perceptual lightness, so the steps are evenly
spaced to the eye rather than evenly spaced in bytes. Dark mode inverts the
ramp — `--grey-0` becomes black, `--grey-1000` becomes white — which is why the
semantic layer below barely changes between themes. See
[dark mode](/docs/dark-mode).

## Semantic tokens

Nothing outside this block should reference `--grey-*` directly. Components read
the semantic names, so retuning the ramp retunes the whole interface.

```css title="app/globals.css"
:root,
.light {
  /* Surfaces */
  --background: var(--grey-0);
  --foreground: var(--grey-1000);
  --card: var(--grey-0);
  --card-foreground: var(--grey-1000);
  --popover: var(--grey-0);
  --popover-foreground: var(--grey-1000);
  --muted: var(--grey-100);
  --muted-foreground: var(--grey-600);
  --subtle: var(--grey-50);

  /* Rules. `--border` is the hairline; `--border-strong` is the ink rule. */
  --border: var(--grey-200);
  --border-strong: var(--grey-1000);
  --input: var(--grey-300);
  --ring: var(--grey-1000);

  /* Emphasis. Inverted ink is the only "accent" the system has. */
  --primary: var(--grey-1000);
  --primary-foreground: var(--grey-0);
  --primary-soft: var(--grey-100);
  --accent: var(--grey-1000);
  --accent-foreground: var(--grey-0);
  --accent-soft: var(--grey-100);
  --secondary: var(--grey-100);
  --secondary-foreground: var(--grey-1000);

  /* Status — achromatic by design. See below. */
  --destructive: var(--grey-1000);
  --destructive-foreground: var(--grey-0);
  --success: var(--grey-700);
  --warning: var(--grey-700);

  --code-bg: var(--grey-50);
  --selection: oklch(0 0 0 / 0.14);

  /* Shape — square by default. Swiss grids do not round their corners. */
  --radius: 0rem;

  /* Motion */
  --duration-instant: 80ms;
  --duration-fast: 140ms;
  --duration-base: 200ms;
  --duration-slow: 320ms;
  --ease-out-soft: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in-out-soft: cubic-bezier(0.65, 0, 0.35, 1);
}
```

Then map them onto utilities with `@theme inline` — see
[Tailwind setup](/docs/tailwind-setup).

## Token reference

| Token | Purpose |
| --- | --- |
| `--grey-0` … `--grey-1000` | The ramp. Everything else aliases onto it |
| `--background` / `--foreground` | Page surface and body text |
| `--card` / `--card-foreground` | Panel surfaces, bounded by a rule rather than raised |
| `--popover` / `--popover-foreground` | Floating surfaces — menus, dialogs |
| `--muted` / `--muted-foreground` | Recessed fill and secondary text |
| `--subtle` | The quietest fill; asides, table zebra, code chrome |
| `--border` | Structural hairline |
| `--border-strong` | Ink rule for emphasis, hover and selected states |
| `--input` | Form control boundary |
| `--ring` | Focus outline |
| `--primary` / `--primary-foreground` | Inverted-ink emphasis; the primary action |
| `--primary-soft` | Flat fill for a selected or held state |
| `--secondary` / `--secondary-foreground` | Quiet fill with normal ink on top |
| `--destructive` / `--success` / `--warning` | Status, achromatic |
| `--code-bg` | Code block and inline code fill |
| `--selection` | Text selection wash, the one token using alpha |
| `--radius` | Base radius. `0rem`; the derived scale is zero throughout |
| `--duration-*` / `--ease-*` | Motion timing |

## Status without colour

`--destructive`, `--success` and `--warning` are deliberately achromatic. They
resolve to ink and to `--grey-700`, which means they are indistinguishable from
each other on luminance alone in some contexts. That is intentional, and it
carries one hard requirement:

<Callout variant="warning">
  A status token is never sufficient on its own. Pair it with an icon **and** a
  spelled-out text label. Anything that would have relied on red-versus-green to
  communicate must communicate in words instead.
</Callout>

In practice this is the rule that already satisfies WCAG 1.4.1 — the palette
simply removes the option of getting it wrong. A component that renders a state
does so with a glyph and a label, and uses weight or an ink rule to raise its
priority:

```tsx
<p className="flex items-center gap-2 text-foreground">
  <AlertTriangle aria-hidden="true" className="size-4" />
  <span className="font-medium">Payment failed</span>
</p>
```

## Shape and motion

There is one shape token and it is zero:

```css
:root {
  --radius: 0rem;
}
```

The Tailwind scale (`--radius-xs` through `--radius-3xl`) is pinned to zero as
well, so `rounded-lg` on a component is a no-op rather than a surprise.
`rounded-full` is left alone, because a pip or an avatar is a circle rather than
a rounded rectangle.

Durations and easings are tokens for the same reason colours are — so timing
stays consistent across components you installed months apart:

```tsx
className="transition-colors duration-[var(--duration-fast)] ease-[var(--ease-out-soft)]"
```

## Retuning the ramp

Rebranding here is not a hue change; there is no hue. It is a change of contrast
and of where the greys sit. Edit the ramp, leave the semantic layer alone, and
every component moves with it:

```css title="app/globals.css"
:root {
  /* A softer ramp: paper instead of white, graphite instead of black. */
  --grey-0: oklch(0.98 0 0);
  --grey-1000: oklch(0.18 0 0);
  --grey-200: oklch(0.88 0 0);
  --grey-600: oklch(0.46 0 0);
}
```

<Callout variant="tip">
  Keep chroma at zero. If you do add hue, add it to the ramp only, never to an
  individual component — and re-check every contrast pair in the table below,
  because a tinted grey is almost never as light as it looks.
</Callout>

## Scoped themes

Tokens are inherited custom properties, so any subtree can override them. This
is a supported pattern, not a hack — inverting a section is a token swap:

```tsx
<section
  style={{
    "--background": "var(--grey-1000)",
    "--foreground": "var(--grey-0)",
    "--border": "var(--grey-700)",
  } as React.CSSProperties}
>
  <YourComponent>Inverted panel</YourComponent>
</section>
```

The same mechanism powers the theme switch on every preview — see
[dark mode](/docs/dark-mode).

## Component-level overrides

Every component merges `className` last through `cn`, so `twMerge` resolves the
conflict in your favour:

```tsx
<YourComponent className="border-border-strong bg-subtle p-8" />
```

Where a component owns more than one surface, it exposes a second class hook
rather than making you fight selectors:

```tsx
<YourComponent className="border-border-strong" innerClassName="bg-subtle p-8" />
```

## Contrast

The ramp is built around pure black on pure white, so the headline pairs are at
the top of the scale in both themes:

| Pair | Light | Dark |
| --- | --- | --- |
| `--foreground` on `--background` | 21:1 | 21:1 |
| `--primary-foreground` on `--primary` | 21:1 | 21:1 |
| `--muted-foreground` on `--background` | 7.8:1 | 7.3:1 |
| `--muted-foreground` on `--muted` | 6.7:1 | 6.9:1 |

`--muted-foreground` is the one to watch. It carries most of the body copy and
it is the token people lighten first when a page feels heavy; it has roughly
three steps of headroom above 4.5:1 and no more.

Note what the rules are and are not doing. `--border-strong` and `--ring` are
pure ink, so any boundary that has to be perceivable — focus rings, selected
states, the outline of a control — clears 3:1 with room to spare. `--border` is
a structural hairline at around 1.3:1 and is not trying to meet that threshold.
Where a boundary is the only thing identifying an interactive control, reach for
`--border-strong`.
